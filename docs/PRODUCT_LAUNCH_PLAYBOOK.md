# 产品化上线手册（Product Launch Playbook）

版本：v1.1
日期：2026-04-27
适用项目：cpp-ai-chat-server

---

## 1. 目标与原则

本手册用于把当前聊天服务器从“可开发/可演示”推进到“可公开 Beta 上线（阶段 B）”。

推进原则：

- 先可控上线，再规模化扩展。
- 每个阶段必须有验收标准，未达标不进入下一阶段。
- 安全、可观测、可回滚优先于新功能。

---

## 2. 当前状态评估（2026-04-24）

### 已具备

- 后端核心功能闭环：用户、好友、私聊、群聊、AI、历史。
- 前端可用：主要页面与交互可运行。
- CI 与分支保护已落地：PR 合并流程已跑通。
- 文档基础较完整：部署、Docker、测试、开发日志均有沉淀。

### 主要缺口

- 公网 HTTPS/WSS 已落地，但缺少证书轮换、到期告警与反代配置巡检自动化。
- 监控告警已有基础能力，但慢查询、端到端延迟、告警降噪和值班闭环仍未补齐。
- 发布与回滚流程已固化，但缺少按月演练与时长/RTO 漂移跟踪。
- 缺少运营后台最小能力（封禁、审计、广播、申诉处理）。
- 缺少商用必需的合规文档（隐私政策、用户协议、数据删除流程）。

结论：当前适合“小规模内测”，应先完成阶段 B 后再扩大范围。

## 3. 分阶段上线路线

## 阶段 A：封闭内测（10~100 人）

目标：保证基础稳定与问题可追踪。

### A1 安全基线

- [x] 清理硬编码密钥/Token（脚本、配置、文档）。
- [x] 统一使用环境变量管理密钥（AI_API_KEY 等）。
- [x] 关闭调试级敏感日志（正文、凭据、会话信息）。
- [x] 登录防刷：增加基础限流（IP + 账号维度）。

验收标准：

- 仓库扫描无明文密钥。
- 服务日志不包含敏感凭据。
- 连续错误登录达到阈值可被限制。

### A2 可观测性最小闭环

- [x] 输出结构化日志（至少包含时间、级别、模块、请求ID）。
- [x] 增加健康检查端点（进程、数据库连接状态）。
- [x] 建立基础监控看板：CPU、内存、连接数、错误率。
- [x] 建立告警阈值（例如 5xx 比例、服务不可达）。

验收标准：

- 服务异常能在 5 分钟内被告警发现。
- 日志可定位到一次失败请求的主要链路。

### A3 发布与回滚

- [x] 固化发布步骤（拉代码、构建、迁移、启动、验证）。
- [x] 固化回滚步骤（版本回退、数据回退说明）。
- [x] 每次发布保留变更清单与验证记录。
- [x] 实际完成一次发布 -> 验证 -> 回滚 -> 恢复验证演练。

验收标准：

- 演练一次发布 + 回滚，总时长可控且无数据损坏。

## 阶段 B：公开 Beta（100~1000 人）

目标：可承压、可恢复、可持续运营。

### B1 传输与边界安全

- [x] 全站 HTTPS，WebSocket 使用 WSS。
- [x] 强制 HTTP -> HTTPS 跳转。
- [x] 反向代理安全头（HSTS、X-Frame-Options、CSP 基线）。
- [x] 限制暴露端口，只开放必要入口。

验收标准：

- [x] B1 传输与边界安全：HTTPS/WSS、HTTP->HTTPS、反向代理安全头、端口暴露收敛

### B2 数据与恢复能力

- [x] 制定数据库备份计划（每日全量 + 保留策略）。
- [x] 备份/恢复已在当前环境实跑通过，支持 Docker volume 与本地 SQLite 路径兜底。

验收标准：

- [x] 恢复演练成功，满足定义的 RPO/RTO 目标。

### B3 容量与性能

- [x] 定义并发目标（在线连接、消息吞吐、AI 调用峰值）。
- [x] 进行压测并输出报告（瓶颈、优化项、基线值）。
- [x] 增加关键路径限流（消息发送、AI 请求、登录）。

并发目标（首轮暂定）：

- 在线连接：200
- 消息吞吐：100 msg/s
- AI 调用峰值：10 qps

当前性能基线：

验收标准：

- 在目标并发下，核心接口成功率和延迟达标。
- 日常回归应优先覆盖 200 / 300 / 600 三档，除非需要找上限，否则不必每次都扫更高档位。

### B4 发布治理与门禁稳态

- [x] 固化 perf-gate 失败阈值与告警阈值的区分。
- [x] 将 200 / 300 / 600 回归档位纳入常规发布前检查。
- [x] 补齐发布/回滚演练的月度复核节奏。

月度复核建议：

- 每月复核一次发布/回滚演练记录、perf-gate 变更记录和 200 / 300 / 600 回归档位。
- 若有门禁阈值或并发档位调整，先更新 release checklist 与 perf gate 记录模板，再进入下一轮发布前检查。

验收标准：

- perf-gate 不再误杀正常波动；门禁策略可解释、可复核。

## 10. 部署配置范本（阶段 B）

说明：用于 runbook 执行时快速选型，非最终架构约束。

### 10.1 单机范本（推荐内测/小流量 Beta）

- 入口：1 个 Nginx（HTTPS/WSS）
- 应用：1 个 chat_server 进程
- 数据：1 个 SQLite 数据卷（定时备份）
- 监控：Prometheus + Grafana（单机）
- 适用：100~300 在线

关键关注点：

- 定时备份与恢复演练必须按周执行。
- CPU 或连接数接近阈值时提前准备多实例迁移。

### 10.2 多实例范本（推荐公开 Beta 中高流量）

- 入口：Nginx/LB（HTTPS/WSS，健康检查）
- 应用：2~3 个 chat_server 实例
- 会话：粘性会话或会话一致性策略
- 数据：主数据卷 + 备份卷（保留策略）
- 监控：统一指标看板 + 告警分组
- 适用：300~1000 在线

关键关注点：

- 扩容前先完成 600 并发稳态回归。
- 多实例下优先验证连接稳定性与限流一致性。
