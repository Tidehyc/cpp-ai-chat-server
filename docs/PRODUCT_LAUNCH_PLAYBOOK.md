# 产品化上线手册（Product Launch Playbook）

版本：v1.0  
日期：2026-04-24  
适用项目：cpp-ai-chat-server

---

## 1. 目标与原则

本手册用于把当前聊天服务器从“可开发/可演示”推进到“可内测/可商用上线”。

推进原则：

- 先可控上线，再规模化扩展。
- 每个阶段必须有验收标准，未达标不进入下一阶段。
- 安全、可观测、可回滚优先于新功能。

---

## 2. 当前状态评估（2026-04-24）

### 已具备

- 后端核心功能闭环：用户、好友、私聊、群聊、AI、历史。
- 前端可用：主要页面与交互可运行。
- CI 与分支保护已落地：PR 合并流程已跑通。
- 文档基础较完整：部署、Docker、测试、开发日志均有沉淀。

### 主要缺口

- 公网 HTTPS/WSS 已落地，但缺少证书轮换、到期告警与反代配置巡检自动化。
- 监控告警已有基础能力，但慢查询、端到端延迟、告警降噪和值班闭环仍未补齐。
- 发布与回滚流程已固化，但缺少按月演练与时长/RTO 漂移跟踪。
- 缺少运营后台最小能力（封禁、审计、广播、申诉处理）。
- 缺少商用必需的合规文档（隐私政策、用户协议、数据删除流程）。

结论：当前适合“小规模内测”，不建议直接公开商用。

## 3. 分阶段上线路线

## 阶段 A：封闭内测（10~100 人）

目标：保证基础稳定与问题可追踪。

### A1 安全基线

- [ ] 清理硬编码密钥/Token（脚本、配置、文档）。
- [ ] 统一使用环境变量管理密钥（AI_API_KEY 等）。
- [ ] 关闭调试级敏感日志（正文、凭据、会话信息）。
- [x] 登录防刷：增加基础限流（IP + 账号维度）。

验收标准：

- 仓库扫描无明文密钥。
- 服务日志不包含敏感凭据。
- 连续错误登录达到阈值可被限制。

### A2 可观测性最小闭环

- [x] 输出结构化日志（至少包含时间、级别、模块、请求ID）。
- [x] 增加健康检查端点（进程、数据库连接状态）。
- [x] 建立基础监控看板：CPU、内存、连接数、错误率。
- [x] 建立告警阈值（例如 5xx 比例、服务不可达）。

验收标准：

- 服务异常能在 5 分钟内被告警发现。
- 日志可定位到一次失败请求的主要链路。

### A3 发布与回滚

- [x] 固化发布步骤（拉代码、构建、迁移、启动、验证）。
- [x] 固化回滚步骤（版本回退、数据回退说明）。
- [x] 每次发布保留变更清单与验证记录。

验收标准：

- 演练一次发布 + 回滚，总时长可控且无数据损坏。

## 阶段 B：公开 Beta（100~1000 人）

目标：可承压、可恢复、可持续运营。

### B1 传输与边界安全

- [x] 全站 HTTPS，WebSocket 使用 WSS。
- [x] 强制 HTTP -> HTTPS 跳转。
- [x] 反向代理安全头（HSTS、X-Frame-Options、CSP 基线）。
- [x] 限制暴露端口，只开放必要入口。

验收标准：

- [x] B1 传输与边界安全：HTTPS/WSS、HTTP->HTTPS、反向代理安全头、端口暴露收敛

### B2 数据与恢复能力

- [x] 制定数据库备份计划（每日全量 + 保留策略）。
- [x] 备份/恢复已在当前环境实跑通过，支持 Docker volume 与本地 SQLite 路径兜底。

验收标准：

- [x] 恢复演练成功，满足定义的 RPO/RTO 目标。

### B3 容量与性能

- [x] 定义并发目标（在线连接、消息吞吐、AI 调用峰值）。
- [x] 进行压测并输出报告（瓶颈、优化项、基线值）。
- [x] 增加关键路径限流（消息发送、AI 请求、登录）。

并发目标（首轮暂定）：

- 在线连接：200
- 消息吞吐：100 msg/s
- AI 调用峰值：10 qps

当前性能基线：

- [docs/perf_reports/PERFORMANCE_BASELINE_20260425.md](docs/perf_reports/PERFORMANCE_BASELINE_20260425.md)
- `message_history_benchmark_20260425_085000.txt` 的最新速度比为 59.27x，仍有明显索引收益，但低于历史均值 80% 告警阈值

并发压测结果：

- [docs/perf_reports/concurrent_connections_20260425.md](docs/perf_reports/concurrent_connections_20260425.md)
- `scripts/test_concurrent_connections.py` 在 `wss://127.0.0.1:18443/ws` 上 90/90 通过；`rooms_json` 扩展到 300 并发时重启后为 240/300（80%，受命令限流影响），采用分批发送后为 300/300（100%）；400 并发分批搜索下可达 400/400（batch_size=20, interval=5000ms）；500/600 并发在推荐节奏下仍保持 100%，其中 600 作为当前高档位基线，400/500 仅保留为探索档位
- [docs/perf_reports/concurrent_connections_connect_only_20260425.md](docs/perf_reports/concurrent_connections_connect_only_20260425.md)
- `scripts/test_concurrent_connections.py` 纯连接模式在 `wss://127.0.0.1:18443/ws` 上 200/250/300/400/500/600 并发均通过，成功率 100%；日常回归固定看 200 / 300 / 600 三档
- [docs/perf_reports/concurrency_test_matrix_20260425.md](docs/perf_reports/concurrency_test_matrix_20260425.md)
- 并发压测参数矩阵已整理，作为后续容量回归基线

验收标准：

- 在目标并发下，核心接口成功率和延迟达标。
- 日常回归应优先覆盖 200 / 300 / 600 三档，除非需要找上限，否则不必每次都扫更高档位。

## 阶段 C：商用 GA（1000+ 人）

目标：具备商用可靠性与合规可审计能力。

### C1 合规与法务

- [ ] 隐私政策（数据收集、使用、保留、删除）。
- [ ] 用户协议（服务条款、免责、违规处理）。
- [ ] 数据删除/导出流程（用户可发起，后台可执行）。
- [ ] 审计留痕策略（管理操作与安全事件）。

### C2 运营能力

- [ ] 管理后台最小集：用户封禁/解封、广播、举报处理。
- [ ] 风控策略：异常请求识别、机器人行为限制。
- [ ] 客服与工单流程：问题分级、SLA、回访。

### C3 商业化能力（如收费）

- [ ] 调用配额和账单统计。
- [ ] 套餐策略与超额保护。
- [ ] 成本监控（尤其 AI 调用成本）。

验收标准：

- 关键运营动作可审计、可追责。
- 商业化路径不导致服务风险失控。

## 5. 建议推进节奏（4 周）

第 1 周：阶段 A（安全基线 + 可观测性）  
第 2 周：阶段 A（发布回滚）+ 阶段 B（TLS/WSS）  
第 3 周：阶段 B（备份恢复 + 压测 + 限流）  
第 4 周：阶段 C（合规最小集 + 运营最小集）

每周输出：

- 本周完成项（打勾清单）
- 风险项与阻塞项
- 下周计划

## 7. 执行建议

- 每个阶段单独开分支和 PR，避免大而全改动。
- 每次只做“一个风险主题”并产出验证证据。
- 所有上线动作都要有可回滚方案。

如果需要，可在下一版文档中补充：

- 你的目标用户规模对应的参数模板。
- 单机部署与多实例部署的两套配置范本。
- 上线日作战清单（按小时执行版）。

说明：按“一个风险主题一个分支一个 PR”推进，先收口未合并改动，再补齐 A 阶段剩余闭环。

### Week 1（收口 + 安全 + 可观测）

- 目标：完成密钥扫描、环境变量来源梳理、敏感日志脱敏回归。
- 交付：扫描报告、修复提交、部署文档更新。
- 验收：仓库扫描无明文密钥；日志样本无凭据正文。

3. A2 可观测性补齐（建议分支：`copilot/a2-errorcode-alerting-20260427`）

- 目标：补齐 error_code 分类并落地告警通道（Webhook/企业 IM）。

### Week 2（发布回滚实战 + 性能门禁稳态）

4. A3 发布回滚演练（建议分支：`copilot/a3-release-rollback-drill-20260428`）

- 目标：执行一次完整发布 + 回滚 + 恢复验证，记录时长与风险。
- 交付：演练记录文档、耗时统计、风险清单。
- 验收：回滚成功，无数据损坏，RTO/RPO 在目标内。

- 目标：固化 200/300/600 日常回归档位，区分“告警阈值”与“失败阈值”。
