# 消息已读未读状态功能测试指南

## 📋 新增功能

本次更新实现了以下功能：

### 1. 消息已读未读状态追踪
- 数据库 `messages` 表添加 `is_read` 字段
- 新消息默认 `is_read = 0`（未读）
- 消息被查看后标记为 `is_read = 1`（已读）

### 2. 已读状态 API
- `/read <用户名>` - 标记来自指定用户的消息为已读
- `/unread` - 查询未读消息总数

### 3. 前端已读标识显示
- 自己发送的消息旁显示已读状态：
  - `✓` - 消息已发送但未读
  - `✓✓` - 消息已被对方阅读
- 切换到聊天时自动调用 `/read` 标记消息已读
- 收到消息时如果当前正在与该用户聊天，自动标记已读

## 🐛 已知问题排查

### 问题 1：消息旁一直显示单勾 `✓`

**可能原因：**
- 接收方未查看消息
- `/read` 命令未正确调用

**解决方案：**
1. 确认接收方是否切换到聊天界面
2. 检查浏览器控制台 (F12)，搜索 `/read` 命令
3. 查看后端日志，确认收到 `read_confirm`

### 问题 2：已读状态不更新

**可能原因：**
- 前端状态未正确同步
- WebSocket 连接断开

**解决方案：**
1. 刷新页面重新连接
2. 检查 WebSocket 连接状态（顶部状态栏）
3. 手动发送 `/read <用户名>` 命令

### 问题 3：数据库列不存在错误

**可能原因：**
- 旧数据库未添加 `is_read` 列

**解决方案：**
```bash
sqlite3 /path/to/chat.db "ALTER TABLE messages ADD COLUMN is_read INTEGER DEFAULT 0;"
```
