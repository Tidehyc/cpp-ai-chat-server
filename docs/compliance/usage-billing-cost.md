# 配额、账单与成本监控草案

版本：Draft
更新时间：2026-05-07

## 1. 当前项目现状

当前项目尚未引入真实账单系统，也没有用户级计费产品，但已经有部分能力可作为后续商业化基础：

- AI 请求入口
- 消息发送与搜索
- 连接数与限流
- 备份与恢复
- 基础监控与告警

## 2. 商业化前的最小设计目标

如果后续引入配额或计费，建议至少支持：

- 按用户统计 AI 调用次数
- 按用户或组织统计消息量和导出次数
- 对高成本操作设置限额或配额
- 对异常消耗触发告警
- 对月度成本给出可追踪汇总

## 3. 建议字段

### 3.1 配额

- 用户 ID
- 组织 ID（如有）
- 配额类型：AI / 消息 / 导出 / 管理员操作
- 时间窗口：日 / 周 / 月
- 已用量与剩余额度

### 3.2 账单与成本

- 时间区间
- AI 请求次数与推估成本
- 存储容量
- 备份占用
- 带宽与调用量

## 4. 当前缺口

- 没有真实账单后端
- 没有配额扣减逻辑
- 没有面向用户的用量仪表盘
- 没有成本与收入对账流程

## 5. 后续建议

- 先实现只读用量统计，不直接收费
- 先做月度成本报表，再做自动化账单
- GA 前再决定是否接入真实支付体系
