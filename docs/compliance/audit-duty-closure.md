# 审计留痕与值班闭环草案

版本：Draft
更新时间：2026-05-07

## 1. 当前已有的留痕来源

项目当前已经具备以下可用于审计和复盘的材料：

- `docs/devlog.md`：关键变更与验证记录
- `docs/release_records/`：发布、回滚、演练和安全扫描记录
- `moderation_events`：运营动作审计数据
- `backend-checks`：CI 运行记录与 required checks
- Alertmanager / Prometheus：告警触发与投递记录

## 2. 闭环目标

值班闭环至少应包含以下内容：

- 发现问题：监控或用户反馈发现异常
- 定位问题：通过日志、请求 ID、错误码、审计记录定位
- 处置问题：限流、回滚、修复、沟通
- 留下记录：记录处理人、时间、影响范围、处理结果
- 复盘改进：将问题补充到 devlog 或 release record

## 3. 建议执行规范

### 3.1 线上事件

- 任何告警都应有对应工单或事件记录
- 关键故障处理后，应补一条 devlog 或 release record
- 若涉及用户影响，应保留开始时间、结束时间、影响范围和恢复方式

### 3.2 审计动作

- 封禁、解封、广播、举报处理应保留审计记录
- 重要配置变更应记录前后值与变更原因
- 数据导出、数据删除请求应记录申请时间与执行结果

## 4. 当前缺口

- 尚未形成统一的值班表或 on-call rota
- 尚未有正式的事件编号规范
- 尚未把所有人工操作统一打到单一审计系统

## 5. 后续建议

- 为线上事件定义统一编号
- 将高风险操作补成标准化审计模板
- 明确值班交接与升级路径
